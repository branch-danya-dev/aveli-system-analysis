# Aveli — Local SQLite Physical Schema

## Database Files

| Path | Purpose |
|---|---|
| `documents/aveli_<userId>.sqlite` | Active per-user professional workspace database. |
| `documents/aveli.db` | Legacy single-file database; not automatically attached to an account. |
| `documents/visit_photos/<sanitizedUserId>/` | Binary visit-photo files outside SQLite. |

`LocalDatabaseManager.openForUser(userId)` opens or creates the per-user database.

The legacy `aveli.db` may be claimed only through the explicit legacy-claim path. Closing a workspace closes the connection but does not delete the file. Explicit local-data deletion removes the per-user SQLite file.

Local entity identifiers are UUID v4 values generated by application use cases.

## Relationships

```text
clients      1 ── 0..* appointments
services     1 ── 0..* appointments
appointments 1 ── 0..1 payments
appointments 1 ── 0..* visit_notes
appointments 1 ── 0..* visit_photos
clients      1 ── 0..* visit_photos
```

Confirmed invariant:

> `payments.appointment_id` is UNIQUE, therefore a physical appointment has at most one payment row.

Partial payment is represented inside that one row through `amount_paid` and `status=partial`.

## Intentional Denormalization

The schema intentionally duplicates selected values:

- `appointments.price` snapshots service price at booking time;
- `appointments.payment_status` provides an aggregated UI-oriented payment state;
- `visit_photos.client_id` duplicates the client relation reachable through appointment.

These fields must not be interpreted as accidental duplication.

## Indexes


Other table-specific indexes are documented with their entities.

## Source Consistency Note

The supplied persistence description contains one naming mismatch:

```text

Detailed table:  duration / return_interval
```

The detailed table definition is used in this documentation, but the exact SQL column names should be rechecked against `lib/core/database/tables/*.dart` before treating generated SQL as canonical.
