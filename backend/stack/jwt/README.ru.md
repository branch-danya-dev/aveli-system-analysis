# JWT

> Технология токена доступа для аутентифицированных запросов к бэкенду Aveli.

## Роль

JWT используется как краткоживущий токен Bearer для аутентифицированных запросов API и переносит идентичность пользователя через границу HTTP.

JWT **не является правом доступа к рабочему пространству**:

```text
JWT-аутентификация
      ↓
Аутентифицированный аккаунт
      ↓
Определение доступа
      ↓
Доступ разрешён / запрещён
```

## Почему подходит

Бэкенд Aveli — компактный HTTP API без серверного состояния для каждого токена доступа. JWT позволяет аутентифицировать запрос без отдельной строки токена в базе данных, при этом статус аккаунта всё равно дополнительно проверяется на сервере.

## Использование в Aveli

Конкретный набор полей токена, TTL, формат токена обновления, ротация и поведение при повторном использовании относятся к жизненному циклу аутентификации:

[`../../auth/session-lifecycle.ru.md`](../../auth/session-lifecycle.ru.md)

## Зависимости

- `@nestjs/jwt`
- `passport-jwt`
- `JwtStrategy`
- `JWT_ACCESS_SECRET`
- проверка текущего состояния аккаунта

## Ограничения

Самодостаточный токен доступа может оставаться криптографически действительным до истечения срока, если не реализован дополнительный механизм отзыва.

Работа с секретом подписи критична для безопасности, а набор полей токена становится частью внутреннего контракта аутентификации.

Текущая документация не утверждает, что существует серверный список отозванных токенов доступа.

## Заменяемость

**Средняя.**

Замена JWT затронет защитные компоненты и стратегию NestJS, аутентификацию Flutter по схеме Bearer, выдачу токенов, конфигурацию безопасности и тесты. При сохранении разделения аутентификации и доступа продуктовые правила доступа менять не требуется.

## Альтернативы

Возможны непрозрачные серверные токены доступа, сессии на основе браузерных файлов cookie или другой формат подписанного токена.

Исторического ADR с формальным сравнением альтернатив нет.
