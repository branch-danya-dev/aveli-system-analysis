# Context

> Product background, target users, goals, and positioning of Aveli.

---

## Purpose

The `context/` directory explains **why Aveli exists, who it is designed for, and which user problem the product is intended to solve**.

This area provides the business background required before reading scope, requirements, or technical documentation.

---

## Responsibility

This area is responsible for:

- product purpose;
- target users;
- user problems and needs;
- product positioning;
- product goals and success direction;
- high-level product principles.

---

## Boundaries

Context explains **why the product exists**.

It should not define detailed functional behavior, implementation architecture, technologies, database structure, or API contracts.

Detailed product boundaries belong to `../scope/`.

Detailed behavior belongs to `../requirements/` and `../processes/`.
